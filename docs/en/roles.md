# Roles and maintenance

[Home](../../README.md) · [中文](../zh/roles.md)

Roles describe review responsibility. Public attribution should identify the actual contribution and its evidence; additional individual assignments can be recorded when confirmed.

| Role | Responsibility | Handoff artifact |
|---|---|---|
| Project maintainer | Prioritize Issues, coordinate review, approve releases | Roadmap, release checklist and open-risk register |
| Research contributor | Define hypotheses, baselines, splits and metrics | Proposal and reproducibility record |
| Implementation contributor | Maintain tool, data and state contracts | Focused PR, tests and interface notes |
| Reproduction reviewer | Run or inspect independent evidence | Environment, commands, outputs and discrepancies |
| Tutorial contributor | Explain concepts with accurate examples in both languages | Source links, worked example, exercises and answers |

## Attribution and review

Record conception, implementation, experiments, writing, and review separately when relevant. Repository ownership does not establish authorship of every component. DeerFlow and Qlib provenance is maintained in [third-party notices](../../THIRD_PARTY_NOTICES.md); new contributions should link their Issues and PRs.

## Continuity

For a handoff, record active tasks, confirmed decisions, data-access prerequisites, dependency changes, commands, validation evidence, and the next bounded action. Reference credential variable names, never credential values. Keep review and release ownership visible in Issues so another maintainer can continue from the same evidence.
