# 案例二：从因子假设到研究记忆

[首页](../../README_zh.md) · [English](../en/case-02-factor-lifecycle.md) · [上一个案例](case-01-task-to-backtest.md)

## 目标与前置知识

追踪因子生成、可执行表示、验证、血缘、检索、准入和研究调度。需要理解案例一的数据契约与指标，以及图中父子边的含义。本案例基于源码，手算使用虚构观测值。

主要源码是 [factor_generate_tool.py](../../backend/packages/harness/deerflow/tools/builtins/quant/factor_generate_tool.py)、[quant_mining_tool.py](../../backend/packages/harness/deerflow/tools/builtins/quant/quant_mining_tool.py) 和旁边的 `dag`、`retrieval`、`admission`、`bandit` 目录。[完整文稿](https://github.com/Soros2040/julius-future/blob/main/works/benjamin-agent/manuscript.md)给出历史 Alex-Fin 设计背景，采用**八维**调度向量；当前调度器有**九个字段**。本案例保留这一设计与实现差异。

可以把生命周期理解为一条证据链：假设变为公式与可执行代码，验证产生测量值，DAG 保存血缘与未被接受的想法，检索选择上下文，准入决定是否进入活跃池，调度决定下一步研究因子还是模型。每个边界都有数据契约，前一阶段成功并不意味着后续阶段已经执行。

## 1. 表达一个可证伪的假设

假设“近期价格动量包含对某个明确未来收益的预测信息”，可先构造：

$$f_{i,t}=P_{i,t}/P_{i,t-5}-1.$$

如果今天收盘为 105、五个观测日前为 100，特征就是 `0.05`。Qlib 风格表达式为 `$close / Ref($close, 5) - 1`。使用前要明确今天的收盘价何时可知、何时可以成交。标签属于更晚的区间，不能进入特征构造。

实现同时保存公式与 Python 代码。执行契约要求 `calculate_factor(df)` 返回 Series 或单列 DataFrame，保留股票/日期索引。滞后操作需按股票分组，直接移动展平后的表可能从一只股票错移到另一只股票。

`generate_factors` 准备生成提示并保存待处理上下文；完成该动作不等于公式已经执行和评估。之后的 `validate_and_add_factor` 接收代码，并进入验证与测量路径。待处理提示、生成文本、执行输出、准入节点应分别记录证据。

文稿采用先公式后代码的思路，使金融假设在执行前即可被审阅；采用全局 DAG 上下文，则是为了让新提案参考既有分支、失败反馈和因子池构成。实现把提示准备、验证和图插入暴露为独立动作，因此可以逐段追踪。原图解释阶段设置的动机，源码说明当前实际发生的转换。

## 2. 在恰当层面验证产物

`_execute_factor_code` 写入临时 Python 程序，以 300 秒超时运行子进程，读取 Parquet 输出，最后清理临时文件。该路径在主机执行并继承进程环境。超时限制控制耗时，但不提供隔离。执行不可信提案前，需要审阅代码并使用隔离环境。

[evaluators.py](../../backend/packages/harness/deerflow/tools/builtins/quant/evaluators.py) 提供六项结构检查：

| 检查 | 当前行为 | 能说明什么 |
|---|---|---|
| 无穷值 | 统计 `inf` | 没有无穷数值 |
| 单列 | 要求一列 | 只有一个因子输出 |
| 基本格式 | 检查两个具名索引层和一列 | 表格形状符合约定 |
| 日频 | 独立日期间隔的中位数不超过两天 | 一项频率启发式检查 |
| 行数 | 有参考值时至少达到 99% | 大致覆盖程度 |
| 索引一致性 | 有参考索引时行数比例和重合度均至少 99% | 与参考对齐 |

没有参考时，相应检查可能报告通过，并说明跳过比较。这些检查不能证明无数据泄漏、经济有效性或公式与代码等价；这些结论需要另行验证。因此，格式正确的因子仍可能在决策时点不可用。

## 3. 用 DAG 保存血缘与证据

[DualRepFactorNode](../../backend/packages/harness/deerflow/tools/builtins/quant/dag/knowledge_graph.py) 保存公式、代码、父子 ID、深度、描述、IC 系列指标、被选次数、状态、假设、反馈与决策标志。`FactorDAG.insert` 拒绝重复 ID，连接子节点前要求父节点已经存在。

例如，`momentum_5d` 的子节点可以是改变尺度或条件的 `momentum_5d_scaled`。到根节点的路径解释想法演变，测量值说明每个想法是否有帮助。名称相似不能代替父子关系，关系由父节点 ID 表达。被拒绝或被淘汰的节点仍有历史价值，后续假设可能需要理解一个分支为何停止。

文稿描述的胖节点包括公式、代码、八项指标、拓扑、轨迹与知识。当前 `DualRepFactorNode` 保存公式/代码、血缘、深度、IC 系列指标、反馈、状态和决策字段；ARR、IR、回撤、Sharpe 和 Calmar 没有声明为节点字段，动态附加的值不会被序列化保留。因此，需要区分文稿设计的知识对象和当前代码能完整保存并恢复的字段。

解释时注意：`get_sota` 返回最近被标记为 `decision=True` 的节点，不是一般意义上的指标最大值。`query_code_experience` 当前返回空列表。静态审阅可以先列出挖掘代码写入的字段，再逐项对照 `to_dict` 与 `from_dict`，为后续往返测试明确范围。

## 4. 检索值得继续研究的起点

[BayesianFactorRetriever](../../backend/packages/harness/deerflow/tools/builtins/quant/retrieval/bayesian_retriever.py) 从活跃候选中选择，将 ICIR 导出的质量项与池质量项结合。其质量因子可以概括为：

$$q_i=\sigma(z(|ICIR_i|))\,0.95^{depth_i}\,0.9^{\max(selected_i-2,0)},$$
$$score_i=clip(q_i\,pool_i).$$

`z` 在候选间标准化，`σ` 是 logistic 函数。实现还归一化池得分，可分别为叶子与非叶子保留名额，并增加被检索节点的选择次数。候选不足时直接返回已有节点。

**手算例子。** 假设标准化 ICIR 为 `[-1, 0, 1]`，深度为 `[0, 1, 2]`，被选次数为 `[0, 3, 2]`。质量项约为 `0.269`、`0.5×0.95×0.9=0.428` 和 `0.731×0.95²=0.660`。若池质量项为 `[0.9, 0.6, 0.3]`，综合得分约为 `[0.242, 0.257, 0.198]`。单一全局排序下，中间候选获选；分组名额可能改变最终选择。

类名不等于后验概率已经校准。当前响应相关性函数对标量 IC 计算 `abs(IC_i IC_j)/(abs(IC_i) abs(IC_j)+epsilon)`，两个 IC 非零时几乎总接近一，尚未测量实际因子输出向量相关性。可选语义相似度使用嵌入，可能调用外部 API。编辑距离默认关闭。这些区别直接对应可验证任务。检索还会修改被选次数，因此在真实会话中执行检索会影响后续得分。

## 5. 应用准入规则

[DualAdmissionChecker](../../backend/packages/harness/deerflow/tools/builtins/quant/admission/dual_checker.py) 有两条路径，默认条件为：

- **质量路径 A：** IC 绝对值至少 `0.006`；存在父节点时，ICIR 绝对值还应高于父节点。
- **多样性路径 B：** 存在父节点、IC 达标、ICIR 绝对值高于父节点的 `0.70` 倍，且最大互相关同时低于 `0.45` 和父节点对应值。
- 两条路径均要求最大互相关不超过 `0.9`；池满后淘汰 IC 绝对值最低的成员。

**手算例子。** 父节点 ICIR 为 `0.50`，候选 IC 绝对值 `0.008`、ICIR 为 `0.40`。因为 `0.40 < 0.50`，路径 A 不通过。路径 B 的 ICIR 条件通过，因为 `0.40 > 0.35`。若候选实测最大相关性 `0.30`、父节点对应值 `0.60`，两个多样性条件均满足，候选可经 B 准入。

存在两组因子 Parquet 序列时，检查器对齐索引、使用第一列计算每日 Pearson 相关，并要求最小重合样本。回退逻辑只看标量 IC 符号：同号为一、异号为零。实验记录应明确标注回退，不能据此声称已经测量多样性。

文稿阈值属于另一组研究配置：质量门槛为 `IC > 0.10`，探索比较采用父节点 ICIR 的 `0.90` 倍，互相关阈值为 `0.70`；检索多样性还讨论了响应、语义和编辑距离阈值。每个阈值都应注明来源和配置，将历史数值直接写入当前源码说明会改变这里解释的规则。

## 6. 调度因子研究还是模型研究

[BanditScheduler](../../backend/packages/harness/deerflow/tools/builtins/quant/bandit/scheduler.py) 通过采样线性得分，在 `factor` 和 `model` 两个动作之间选择。当前状态有**九个维度**：

$$x=[IC,ICIR,RankIC,RankICIR,ARR,IR,-MDD,Sharpe,Calmar].$$

奖励函数为 `r = wᵀx`，权重为 `[.10,.10,.05,.05,.25,.15,.10,.15,.05]`。每个动作根据已存均值和精度矩阵逆采样系数，再比较与状态的点积。全零状态下两个得分都为零，由插入顺序选择 `factor`。

各原始指标尺度不同。当前 MDD 为负数，所以 `-MDD` 为正；更深的回撤可能增大奖励中的该项。把调度结果解释为研究进步之前，需要明确审阅奖励尺度与方向。

历史文稿使用八维向量 `[IC, ICIR, RankIC, RankICIR, ARR, IR, -MDD, Sharpe]`，权重为 `[.1,.1,.05,.05,.25,.15,.1,.2]`。当前实现增加 `Calmar`，权重变为 `[.10,.10,.05,.05,.25,.15,.10,.15,.05]`，并从负回撤字段构造 `-mdd`。历史图片说明保留八维背景；当前源码与对应讲解使用九维契约。

标准贝叶斯线性更新通常写作：

$$P'=P+xx^T/\sigma^2,\qquad \mu'=(P')^{-1}(P\mu+xr/\sigma^2).$$

当前 `record` 在等式右侧使用更新后的精度矩阵。用非零先验均值进行第二次更新，可以暴露差异；零均值出发的第一次更新可能掩盖问题。本教程记录差异，保留研究算法供后续审阅。

**手算两次更新。** 简化到一维，使用实现中的先验方差 `10` 和噪声方差 `0.5`，于是 `P₀ = 0.1`、`μ₀ = 0`。连续两次观测 `x = 1, r = 1`。第一次得到 `P₁ = 2.1`、`μ₁ = 2/2.1 = 20/21`，两种算法相同。第二次 `P₂ = 4.1`，标准更新得到 `μ₂ = (2.1 × 20/21 + 2)/4.1 = 40/41 ≈ 0.97561`；等式右侧使用新精度时，得到 `μ₂ = (4.1 × 20/21 + 2)/4.1 = 20/21 + 20/41 ≈ 1.44019`。这是按源码表达式推导的结果，并非实测运行记录。

还需追踪调用方使用的状态构造器：调度器辅助函数构造 `-mdd`，另一个指标辅助函数 `to_state_vector` 则写入原始 `mdd`。即使两个列表都有九个字段，符号约定不同仍会改变含义。

## 7. 理解编排与完成状态

`quant_mining_tool` 暴露组装、调度、检索、生成、验证、回测、准入和更新等阶段处理器，但 `run_mining_loop` 便捷动作当前只进行调度与检索。完整研究循环需显式编排其余阶段，并保存相应证据。文稿八阶段闭环提供设计地图，当前便捷动作实现了其中一部分。

同样，`factor_generate` 的 `pipeline_with_new_factors` 会统计活跃节点，但当前调用 `run_full_pipeline(config)` 时没有传入因子值。回复文字本身不能证明新因子已经进入训练。附加因子集成路径需要特征列验证和消融实验，之后才能评价效果。

## 练习与答案

**A。** 候选通过六项结构检查，是否就不可能使用明天的收盘价？

**答案。** 结构检查没有审计时间信息使用，必须单独测试决策时点的特征可得性。

**B。** 两个因子的 IC 都为 `0.03`，当前检索器得到接近一的“相关性”，能证明输出序列重复吗？

**答案。** 这个值来自标量启发式。应对齐实际输出序列计算相关性，才能讨论冗余。

**C。** 为什么两次 Bandit 更新的测试比从零均值开始只更新一次更有效？

**答案。** 第一次更新后均值可以非零，此时 `P'μ` 与 `Pμ` 的差别会影响结果；初始零均值消除了这一差别。
