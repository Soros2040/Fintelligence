# 角色与维护

[首页](../../README_zh.md) · [English](../en/roles.md)

角色说明审阅责任。公开署名应对应实际贡献与证据；新增个人分工在确认后登记。

| 角色 | 责任 | 交接产物 |
|---|---|---|
| 项目维护者 | 排定 Issue、协调审阅、批准发布 | 路线图、发布清单和已知风险记录 |
| 研究贡献者 | 定义假设、基线、划分及指标 | 研究提案与复现记录 |
| 实现贡献者 | 维护工具、数据及状态契约 | 聚焦 PR、测试与接口说明 |
| 复现审阅者 | 独立运行或检查证据 | 环境、命令、输出及差异 |
| 教程贡献者 | 用双语准确解释概念与例子 | 源码链接、手算、练习及答案 |

## 署名与审阅

需要时分别记录构思、实现、实验、写作和审阅。仓库所有权不代表其中每个组件的作者身份。DeerFlow 与 Qlib 来源保留在[第三方声明](../../THIRD_PARTY_NOTICES.md)，新贡献应关联 Issue 与 PR。

## 持续维护

交接应记录进行中的任务、已确认决策、数据访问前提、依赖变化、命令、验证证据和下一步明确动作。引用凭据变量名，不记录凭据值。让 Issue 中的审阅与发布责任可见，使后续维护者能够沿用同一套证据继续工作。
